# ADR-0003: 操作窓の構造 — 文書・編集の状態・サービス・ビュー

## 状態

採用 (2026-11-09)

## 文脈

[#20](https://github.com/mokume-metal/mokumesh/issues/20) で、操作窓を「階層・入力・ステージ・プロジェクタ配置・出力」のペインに分ける。最初の段 ([#22](https://github.com/mokume-metal/mokumesh/issues/22)) は外枠と階層と出力の出し方で、続く段で各ペインに編集が入る (プロジェクタ配置 [#23](https://github.com/mokume-metal/mokumesh/issues/23)・切り取りと面 [#24](https://github.com/mokume-metal/mokumesh/issues/24)・マスク [#25](https://github.com/mokume-metal/mokumesh/issues/25))。その先には取り消し・メッシュの面・グループ・ブレンドがある。

それまでの操作窓 (1 枚の Form と `AppModel`) には、そのまま広げると壊れる形が 4 つあった。

- **添字で指していた**: 層・出力・領域・出力の窓 (`outputIndex`)・一覧の行 (`id: \.offset`)。並べ替えや削除のあと、選択や窓が別のものを指す
- **状態が 1 つに混ざっていた**: 保存する設定・実行時の出し方・受け手・窓・計測が `AppModel` に同居し、設定を変える口が散らばっていた。保存済みか・取り消し・窓への反映を 1 か所で扱えない
- **絵の取り込みが描く側ごとだった**: 出力の窓が描くたびに受け手から絵を取っていた。描く場所 (ペインとプレビュー) が増えると取り込みが重なり、Syphon は「欲しい映像」の違う取り込みのたびに繋ぎ直す
- **検査が無かった**: アプリのパッケージにはテストが無く、GUI の論理は手で触って確かめるしかなかった

## 決定

### 1. 4 つの層に分け、変化は一方向に流す

| 層 | 中身 | 保存 |
| --- | --- | --- |
| 文書 | `MappingConfig` (ADR-0002 の形) | する (JSON) |
| 編集の状態 | 選択・出力の出し方・ペインの配置 | しない (実行時だけ) |
| サービス | 絵の取り込み (`FrameHub`)・表示装置の監視・描画 (`Renderer`)・出力の窓 | — |
| ビュー | 階層・各ペイン・inspector (SwiftUI) | — |

ビューは意図を送るだけで、文書を直接書き換えない。文書が変わると、そこから窓と描画が追従する。組み立ては `AppDelegate` の 1 か所で行い、本番 (`--config`)・計測 (`--measure`)・編集の 3 通りは組み立て方の違いとして表す。

### 2. 文書を変える口は 1 本にする

`EditorDocument.perform(_ actionName:, _ body: (inout MappingConfig) -> Void)` だけが設定を変える。前後の snapshot を比べ、取り消しの登録・未保存の印・検証・変更の知らせをここで一括して扱う。ドラッグは `beginGesture` / `endGesture` で挟み、何度動かしても取り消しは 1 回にまとめる。

操作の種類を閉じた enum (Command パターン) にはしない。操作を足すたびに enum と分岐の両方を直すことになり、ペインごとに編集が増える #23 以降で重くなる。取り消しは値の snapshot で足りる (設定は小さな値型である)。

### 3. 面・マスク・出力・領域に、保存される ID を持たせる

選択・出力の窓・取り消し後の選択の戻し・後のグループやマスクの参照・ブレンドの組は、どれも「並べ替えても変わらない参照」を要る。ID は型で分け (`MappingConfig.SurfaceID` など)、取り違えをコンパイラに止めさせる。

- 新しく作るものには UUID を振る
- 書かれていない設定 (手で書いたもの・版 1 からの読み替え) は、読むときに**決定的に**振る (`surface-1` のように、既にある ID と重ならない番号)。読むたびに違う ID になると、同じファイルを読んだ結果が等しくならない
- 同じ ID が 2 度あれば読まない (手で複製したときに起きる)

版 2 は ID を持つ前にまだ配っていないので、版は上げずに任意の項目として足す。

### 4. 純粋な論理は、検査できる場所に置く

- 設定そのものへの操作 (層の挿入・削除・移動・名前の変更、ID から添字への解決) は `MokumeshMapping` に置く。前例は `movingCorner` で、根の `swift test` が検査する
- 編集の状態 (文書・選択・階層の並び・出し方の計画・座標の写し・ペインの配置) は、アプリのパッケージのライブラリ `MokumeshEditor` に置く。AppKit と SwiftUI に依存させず、`swift test --package-path App` で検査する (`make test` が両方を回す)

`MokumeshEditor` を根に置かないのは、エディタの状態を送り手の利用者向けの公開の口 (product) に晒さないためである。根の役目は受け渡しの約束と設定の形で、アプリを分けた理由 (根の `Package.swift` の冒頭) と同じ線を引く。

### 5. 座標の写しは `Viewport` の 1 つに集める

ペインはそれぞれ別のモデルの空間を見る (ステージの画素・映像の 0〜1・領域の 0〜1)。モデルの空間とビューの点の往復 (縦横比を保った収め方・上下の反転・後のズームとパン) を `Viewport` が持ち、Metal に描く範囲と、上に重ねる目印と、クリックの当たり判定が同じ関数を通る。絵と目印がずれない。

### 6. 描画は 1 つの `Renderer` を使い回す

ペインは「仮想の領域」を作って `Renderer.draw` に渡す。ステージのペインは「受け持つ範囲がステージの外形全体で、台形補正の無い領域」、入力のペインは「映像全体を覆う面を、映像の大きさの範囲で映す領域」である。描き方は出力の窓と同じなので、ペインで見えるものと映るものが食い違わない。

絵は `FrameHub` が 1 か所で取る。表示の更新ごとに高々 1 回取り、欲しい映像は「文書の面が使う映像 ∪ 選んだ入力」とする。計測 (`--measure`) の提示の時刻は出力の窓からだけ取り、ペインの提示を混ぜない。

### 7. 出力の出し方は、望んだ状態と効いている状態を分ける

出し方は `プレビューのみ / 別窓 / 全画面` の 3 つで、出力ごとに編集の状態として持つ。全画面の先の表示装置は設定の `display` を正とし、二重に持たない (選び直すのは文書の編集で、保存され、取り消せる)。

表示装置が外れても望んだ状態は書き換えない。窓は「望んだ状態と、いま繋がっている表示装置」から開くべき組を計画し、いま開いている窓との差分だけを開け閉めする。繋ぎ直すと元の出し方に戻る。

### 8. macOS の作法に乗る

- 外枠は `NSSplitViewController` (階層・内容・inspector の 3 項目。中身は SwiftUI)。仕切りの位置は `autosaveName` で残る
- メニューは標準の selector (`toggleSidebar:`・`toggleInspector:`・`delete:`・`undo:`・`saveDocument:` など) と responder chain で繋ぎ、使えるかどうかは `NSMenuItemValidation` で決める
- 取り消しは 1 つの `UndoManager` を操作窓と出力の窓で共有する
- 窓の題に未保存の印とファイルを出す

**退けた案**:

- **NSDocument**。保存・取り消し・最近使ったファイルが揃うが、窓を開かない本番の起動とコマンドラインの引数による起動の形に合わない。必要な作法 (未保存の印・取り消し) だけを借りる
- **SwiftUI の App のライフサイクル**。同じ理由で、窓の無い本番の起動を素直に書けない
- **外部の状態管理 (TCA など)**。依存が増えるうえ、決定 2 の 1 本の口で足りる
- **添字のままの選択・実行時だけの ID**。添字は並べ替えで壊れる。実行時だけの ID を設定と並べて持つと、2 つの並びがずれる
- **`HSplitView` / `VSplitView` で 2×2 を組む**。比率を読み書きできず、ペインの最大化や畳みを作れない。比率から描く自前の格子にする
- **`NavigationSplitView` と `.inspector` を `NSHostingController` で包む**。toolbar とメニュー (`toggleSidebar:`) の橋渡しが AppKit のライフサイクルの下では確かでない

**代償**:

- 設定の JSON に ID が増え、差分が少し長くなる
- `MokumeshEditor` は AppKit を知らないので、表示装置などは AppKit を抜いた値に写してから渡す手間がある

## 影響

- 続く段 (#23・#24・#25) は、ペインの中の編集を `perform` / `beginGesture` / `endGesture` と `Viewport` の上に足す。編集の道具の型 (tool) は、#23 で 2 つ目の道具が要るときに決める
- ADR-0002 の「影響」にある GUI のペインの割り当ては、この ADR の層の上で作る
